# Волга‑IT · Финал по информационной безопасности

### Полевой справочник по Web и Linux для подготовки команды

**Версия:** `0.1` · **Формат:** команды → что искать → следующее действие  
**Назначение:** учебные стенды, CTF и разрешённые организаторами цели.

> [!IMPORTANT]
> **Статус источников.** Исходный файл с разбором финала в этой переписке не приложен. Поэтому приведённые ниже команды — **проверочный плейбук**, а не утверждение, что именно их применяли на финале Волга‑IT. Подтверждённых исходником путей до флагов пока **0**. Они будут добавляться в раздел **«Разобранные цепочки до флагов»** с точными командами и доказательствами.

---

## 0. Маршрут на финале: порядок действий

| Шаг | Что сделать | Результат |
|:--|:--|:--|
| **01 · Recon** | Найти открытые TCP-порты, определить службы и версии | Карта поверхности атаки |
| **02 · Web** | Проверить главную страницу, заголовки, `robots.txt`, типовые файлы и каталоги | Список точек входа |
| **03 · Discovery** | Подобрать скрытые пути, расширения, виртуальные хосты (при наличии домена) | Найденные страницы, бэкапы, API |
| **04 · Access** | Проверить обнаруженные уязвимости **только** в пределах задания | Подтверждённая точка доступа |
| **05 · Linux enum** | Определить пользователя, права, задания, сервисы, секреты и необычные файлы | Возможные маршруты к флагам |
| **06 · Flags** | Проверить артефакты и доступные файлы, зафиксировать способ получения | Воспроизводимая цепочка |

**Правило:** каждый найденный путь записывать как `находка → команда → вывод → вывод о риске → дальнейший шаг`. `200 OK` не означает, что там лежит флаг; `403 Forbidden` не означает, что путь не существует.

## 1. Переменные и журнал сессии

Все команды выполняются **на своей Kali/атакующей машине**, если явно не указано `TARGET SHELL`.

```bash
export TARGET="10.10.10.10"         # IP учебной цели
export BASE="http://$TARGET"       # изменить на https:// или нужный порт
export DOMAIN="example.lab"        # только если в задании есть домен

mkdir -p scans evidence
script -q -f evidence/terminal.log  # начать журнал; выйти командой exit
```

> IP, URL и домен выше — **заглушки**, не реальные адреса финала. В командах ниже подставляйте выданную организаторами цель.

## 2. Сеть: определить, что открыто

### 2.1. TCP-сканирование

```bash
# Все TCP-порты. Для стендов с нестабильной сетью уменьшить скорость.
nmap -Pn -p- --min-rate 1000 -T4 -oA scans/all_tcp "$TARGET"

# Точные версии и базовые NSE-проверки — подставить НАЙДЕННЫЕ порты
nmap -Pn -sC -sV -p 22,80,443 -oA scans/services "$TARGET"

# Если подозреваются UDP-сервисы и они входят в область задания
sudo nmap -Pn -sU --top-ports 20 -oA scans/top_udp "$TARGET"
```

**Смотреть:** нестандартные HTTP-порты (`8080`, `8000`, `5000`, `3000`), SSH (`22`), FTP (`21`), SMB (`445`), NFS (`2049`), базы данных (`3306`, `5432`, `6379`). Не принимать эти порты за найденные — это **ориентиры**.

### 2.2. Быстрые проверки по найденной службе

| Служба | Команда с Kali | Проверка |
|:--|:--|:--|
| **HTTP/HTTPS** | `curl -k -i "$BASE/"` | Код ответа, редирект, cookies, сервер |
| **SSH** | `nmap -sV -p22 "$TARGET"` | Наличие и версия SSH |
| **FTP** | `nmap -sV -p21 --script ftp-anon "$TARGET"` | Разрешён ли anonymous-доступ |
| **SMB** | `smbclient -L "//$TARGET" -N` | Перечень доступных ресурсов без пароля |
| **NFS** | `showmount -e "$TARGET"` | Экспортируемые каталоги |
| **TLS** | `openssl s_client -connect "$TARGET:443" -servername "$DOMAIN" </dev/null` | Сертификат, имя хоста |

Запускайте проверку **только если соответствующая служба обнаружена и разрешена правилами**. Инструменты могут отсутствовать в базовой Kali — это не ошибка цели.

## 3. Web: проверки до эксплуатации

### 3.1. Ответ сервера, заголовки, редиректы, исходный HTML

```bash
curl -k -i "$BASE/"                        # статус, headers и ответ
curl -k -I "$BASE/"                        # только headers (HEAD поддерживается не всегда)
curl -k -sSL "$BASE/" -o evidence/index.html

grep -Ein 'TODO|FIXME|admin|debug|api|flag|secret|token' evidence/index.html
```

**Проверить:** комментарии в HTML, ссылки на JavaScript, формы, cookie-флаги, заголовок `Location`, endpoint'ы в JS. Редиректы важно смотреть как **без `-L`**, так и с ним.

### 3.2. `robots.txt` и карта сайта — обязательно

```bash
curl -k -i "$BASE/robots.txt"
curl -k -i "$BASE/sitemap.xml"

# Если robots.txt перечисляет /hidden/ или /backup/ — проверить буквально эти пути:
curl -k -i "$BASE/hidden/"
curl -k -i "$BASE/backup/"
```

**Искать:** директивы `Disallow`, забытые каталоги админки, бэкапы, test/dev-разделы. `robots.txt` **не предоставляет доступ**, но часто выдаёт имена маршрутов.

### 3.3. Короткий список файлов и маршрутов

Проверять **на каждом веб-порту и для каждого обнаруженного виртуального хоста**.

| Путь | Зачем проверяем |
|:--|:--|
| `/robots.txt` | Скрытые или запрещённые для индексации маршруты |
| `/sitemap.xml` | Дополнительные URL и разделы |
| `/.well-known/security.txt` | Служебная информация и контакты |
| `/.git/HEAD`, `/.git/config` | Случайно опубликованный Git-репозиторий |
| `/.svn/entries` | Следы старой системы контроля версий |
| `/.env`, `/.env.bak` | Утечки переменных окружения и секретов |
| `/config.php.bak`, `/config.json`, `/settings.py` | Резервные копии или исходные конфигурации |
| `/backup/`, `/backups/`, `/backup.zip`, `/site.zip` | Архивы и копии веб-приложения |
| `/admin/`, `/login`, `/dashboard/` | Панели и формы аутентификации |
| `/dev/`, `/test/`, `/staging/`, `/old/` | Неактуальные или тестовые версии |
| `/uploads/`, `/files/`, `/download/` | Загружаемые и выдаваемые файлы |
| `/api/`, `/api/docs`, `/swagger-ui/`, `/swagger.json`, `/openapi.json` | API и его документация |
| `/phpinfo.php`, `/server-status`, `/debug/` | Диагностические страницы |
| `/flag.txt`, `/flag`, `/flags/` | **Типовые CTF-гипотезы**, не подтверждённые финалом |

**Проверка вручную:**

```bash
curl -k -i "$BASE/.git/HEAD"
curl -k -i "$BASE/.env"
curl -k -i "$BASE/backup.zip"
curl -k -i "$BASE/api/docs"
```

**Проверка набора автоматически:**

```bash
cat > scans/web_paths.txt <<'PATHS'
/robots.txt
/sitemap.xml
/.well-known/security.txt
/.git/HEAD
/.git/config
/.svn/entries
/.env
/.env.bak
/config.php.bak
/config.json
/settings.py
/backup/
/backups/
/backup.zip
/site.zip
/admin/
/login
/dashboard/
/dev/
/test/
/staging/
/old/
/uploads/
/files/
/download/
/api/
/api/docs
/swagger-ui/
/swagger.json
/openapi.json
/phpinfo.php
/server-status
/debug/
/flag.txt
/flag
/flags/
PATHS

while IFS= read -r path; do
  curl -k -sS -o /dev/null \
    -w '%{http_code}\t%{size_download}\t%{url_effective}\n' \
    "$BASE$path"
done < scans/web_paths.txt | tee scans/web_paths_results.tsv
```

**Интерпретация:** `200` — посмотреть тело, `301/302` — посмотреть `Location`, `401/403` — URL потенциально существует, `404` — вероятно не найден. При одинаковых размерах ответов проверить **кастомную 404** или SPA-fallback.

### 3.4. Скрытые директории и расширения (`ffuf`)

```bash
# Перебор путей. -ac помогает отфильтровать одинаковые ложные ответы.
ffuf -u "$BASE/FUZZ" \
  -w /usr/share/wordlists/dirb/common.txt \
  -ac -mc all -rate 30 -t 10 \
  -of json -o scans/ffuf_dirs.json

# Проверка популярных расширений в именах файлов
ffuf -u "$BASE/FUZZ" \
  -w /usr/share/wordlists/dirb/common.txt \
  -e .php,.txt,.html,.bak,.zip,.old \
  -ac -mc all -rate 30 -t 10 \
  -of json -o scans/ffuf_files.json
```

Если нет `ffuf`, альтернатива:

```bash
gobuster dir -u "$BASE" \
  -w /usr/share/wordlists/dirb/common.txt \
  -x php,txt,bak,zip -k -o scans/gobuster.txt
```

**Принцип:** сначала короткий словарь, затем расширение только для интересных каталогов. Не сканировать бесконечно всё подряд. Учитывать лимиты организаторов.

### 3.5. Виртуальные хосты и домены (только если есть домен)

```bash
dig +short "$DOMAIN"

# Имена в Host могут показывать другую версию сайта на том же IP.
ffuf -u "http://$TARGET/" \
  -H "Host: FUZZ.$DOMAIN" \
  -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt \
  -ac -mc all -rate 30 -t 10 \
  -o scans/vhosts.json -of json
```

Если путь к словарю отсутствует, сначала проверить установленные словари:

```bash
find /usr/share/wordlists /usr/share/seclists -type f \
  \( -iname '*directory*' -o -iname '*subdomain*' -o -name 'common.txt' \) \
  2>/dev/null | head -n 30
```

### 3.6. От HTML к JavaScript и API

```bash
# Собрать адреса JS-файлов из HTML (относительные пути потребуют учёта BASE)
grep -Eo '<script[^>]+src="[^"]+' evidence/index.html | sed 's/.*src="//'

# Проверить опубликованные endpoint'ы API (только если они выявлены)
curl -k -i "$BASE/api/"
curl -k -i "$BASE/openapi.json"
```

**Искать:** ссылки в скриптах, параметры `file=`, `path=`, `id=`, `url=`, методы API, незащищённые панели. **Не считать примерный URL существующим, пока нет ответа сервера.**

## 4. Linux: проверки после получения разрешённого доступа

> **`TARGET SHELL`** — эти команды вводятся **внутри целевой Linux-машины** (например, через выданный доступ или shell в CTF), а не на своей Kali.

### 4.1. Базовый контекст пользователя

```bash
whoami; id; groups
hostname; uname -a; cat /etc/os-release
pwd; ls -lah
printf 'HOME=%s\nPATH=%s\n' "$HOME" "$PATH"
```

**Смотреть:** текущие права, членство в нестандартных группах, домашний каталог, необычный `PATH`, версии ПО. Само по себе наличие старого ядра ещё не доказывает уязвимость.

### 4.2. Пользователи, домашние папки, доступные файлы

```bash
getent passwd
ls -lah /home /root /opt /srv /var/www /tmp 2>/dev/null
find /home /opt /srv /var/www -maxdepth 3 -type f -readable 2>/dev/null | head -n 100
```

**Смотреть:** неочевидные аккаунты, `.ssh`, старые копии, текстовые заметки, конфиги сайта, домашние папки других пользователей, которые реально доступны текущему пользователю.

### 4.3. Поиск артефактов и файлов, похожих на флаги

```bash
# По ИМЕНАМ файлов. Не предполагать, что все флаги называются flag.txt.
find /home /var/www /opt /srv /tmp -type f \
  \( -iname '*flag*' -o -iname '*proof*' -o -name 'user.txt' -o -name 'root.txt' \) \
  -print 2>/dev/null

# По ТЕКСТУ в доступных файлах. Формат флага может быть другим.
grep -RIlE 'flag\{|ctf\{' /home /var/www /opt /srv 2>/dev/null | head -n 50
```

**Важно:** флаги могут храниться в содержимом конфигов, выводе программы, БД, веб-ответах, а не только в `/flag.txt` или `/root/root.txt`.

### 4.4. `sudo`: первое место для проверки повышения прав

```bash
sudo -l
command -v sudo
sudo --version | head -n 2
```

**Смотреть:** команды, выполняемые от другого пользователя без пароля (`NOPASSWD`), разрешённые исполняемые файлы, ограничения аргументов и окружения. Затем анализировать **конкретную** разрешённую команду и её зависимости.

### 4.5. SUID / SGID, Linux capabilities

```bash
# SUID: исполняемые файлы, запускающиеся с правами владельца
find / -type f -perm -4000 -print 2>/dev/null

# SGID: аналогично для группы
find / -type f -perm -2000 -print 2>/dev/null

# Capabilities: дополнительные возможности без полного root
getcap -r / 2>/dev/null
```

**Смотреть:** бинарники вне типового системного набора, интерпретаторы, копии стандартных утилит в `/opt` и `/usr/local/bin`. **Не считать каждый SUID уязвимостью**: важны владелец, права, назначение и реальное поведение.

### 4.6. Cron / systemd timers / задания от root

```bash
crontab -l 2>/dev/null
cat /etc/crontab 2>/dev/null
ls -lah /etc/cron.d /etc/cron.daily /etc/cron.hourly 2>/dev/null
systemctl list-timers --all --no-pager 2>/dev/null
```

**Смотреть:** запускаемые скрипты, владельцев и права на запись. Сам факт записи в общий `/tmp` не даёт повышения прав; нужна **доказанная зависимость** привилегированного задания от изменяемого файла.

### 4.7. Сетевые службы и локальные процессы

```bash
ss -lntup 2>/dev/null
ip -br address; ip route
ps auxww | head -n 80
systemctl --type=service --state=running --no-pager 2>/dev/null
```

**Смотреть:** сервисы, слушающие только `127.0.0.1`, процессы от root, пути к их бинарникам и конфигам. Недоступный извне порт может быть доступен **локально** — если это входит в разрешённую задачу.

### 4.8. Конфигурации и возможные секреты

```bash
# Сначала найти релевантные файлы, не печатая все секреты на экран.
find /var/www /opt /srv /home -type f \
  \( -name '.env' -o -iname '*config*' -o -name '*.ini' \
     -o -name '*.yml' -o -name '*.yaml' -o -name '*.sql' \
     -o -iname '*backup*' \) -print 2>/dev/null | head -n 100

# Только ИМЕНА файлов со словами-индикаторами
# (запускать на доступных в задании каталогах)
grep -RIlEi 'password|passwd|db_pass|secret|api[_-]?key|token' \
  /var/www /opt /srv 2>/dev/null | head -n 50

# Текущие переменные окружения пользователя
env | sort
```

**Типовые источники:** `.env`, файлы приложения, `docker-compose.yml`, резервные `.sql`, конфиги БД, пользовательские скрипты. Секреты не помещать в общий командный отчёт без редактирования.

### 4.9. Права на файлы и директории

```bash
# Каталоги, в которые текущий пользователь действительно может писать
find /etc /opt /srv /usr/local/bin /var/www -type d -writable -print 2>/dev/null

# Записываемые файлы в системных/прикладных местах
find /etc /opt /srv /usr/local/bin /var/www -type f -writable -print 2>/dev/null

# Проверка владельца/прав найденного конкретного файла
namei -l /path/to/suspicious/file
stat /path/to/suspicious/file
```

**Смотреть:** привилегированный сервис читает или исполняет файл, который можно изменять; небезопасные права у конфигов или заданий. Одной записи в файл недостаточно для доказательства цепочки.

### 4.10. Контейнеры, монтирования, окружение

```bash
cat /proc/1/cgroup 2>/dev/null
cat /proc/1/mountinfo 2>/dev/null | head -n 30
mount | head -n 60
ls -l /var/run/docker.sock 2>/dev/null
id
```

**Смотреть:** запуск в контейнере, доступные монтирования, членство в группе `docker`, доступность Docker socket. Подозрительный сокет — **направление для анализа**, а не автоматически доказанный доступ к host.

### 4.11. История, SSH, логи — только разрешённые чтением

```bash
ls -lah ~/.ssh ~/.bash_history ~/.zsh_history 2>/dev/null
ls -lah /var/log/nginx /var/log/apache2 /var/log 2>/dev/null | head -n 60
journalctl -n 100 --no-pager 2>/dev/null
```

**Смотреть:** оставленные администратором подсказки, пути в логах, имена дополнительных сервисов. Не распространять найденные закрытые ключи и пароли.

## 5. Linux: конкретные пути, которые нужно просмотреть

Это **маршрутная карта для проверки**, а не перечень подтверждённых мест хранения флагов Волга‑ИТ.

| Файл / каталог | Что искать | Минимальная команда на `TARGET SHELL` |
|:--|:--|:--|
| `/home/` | Аккаунты, доступные пользовательские файлы | `ls -la /home` |
| `~/.ssh/` | Конфиги и права на SSH-файлы | `ls -la ~/.ssh` |
| `~/.bash_history` | История команд текущего пользователя | `ls -l ~/.bash_history` |
| `/var/www/`, `/var/www/html/` | Исходники сайта, конфиги, бэкапы | `ls -la /var/www /var/www/html` |
| `/opt/`, `/srv/` | Развернутые приложения и служебные скрипты | `ls -la /opt /srv` |
| `/tmp/`, `/var/tmp/`, `/dev/shm/` | Временные файлы и артефакты | `ls -la /tmp /var/tmp /dev/shm` |
| `/var/backups/` | Системные резервные копии | `ls -la /var/backups` |
| `/etc/passwd` | Учётные записи, shell и домашние каталоги | `cat /etc/passwd` |
| `/etc/group` | Группы и назначенные пользователи | `cat /etc/group` |
| `/etc/crontab`, `/etc/cron.d/` | Задания и пути к скриптам | `cat /etc/crontab; ls -la /etc/cron.d` |
| `/etc/systemd/system/` | Самописные сервисы и таймеры | `ls -la /etc/systemd/system` |
| `/etc/ssh/sshd_config` | SSH-настройки при наличии доступа | `cat /etc/ssh/sshd_config` |
| `/proc/self/environ` | Переменные окружения текущего процесса | `tr '\0' '\n' </proc/self/environ` |
| `/var/log/` | Логи сервисов и системных событий | `ls -la /var/log` |
| `/root/` | Root-owned файлы, **только при законном доступе** | `ls -la /root` |
| `/flag.txt`, `/root/root.txt`, `/home/*/user.txt` | Возможные имена флагов **в CTF**, не стандарт Linux | `find /home /root -name 'user.txt' -o -name 'root.txt' 2>/dev/null` |

`Permission denied` — **сигнал о границе прав**, а не повод предполагать, что файл отсутствует.

## 6. Как решать, что проверять дальше

| Если нашли… | Следующая обоснованная проверка |
|:--|:--|
| `Disallow: /secret/` в `robots.txt` | Запросить точный URL, выяснить код ответа и содержимое |
| `/.git/HEAD` читается | Проверить возможность утечки исходного кода и секретов в репозитории |
| `.env` или `config.php.bak` доступен | Определить, к каким **разрешённым** сервисам относятся настройки |
| `/api/docs` или OpenAPI | Выписать реальные endpoint'ы, методы и требования авторизации |
| Необычный HTTP-порт | Проверить его как **отдельное** веб-приложение |
| В `sudo -l` есть разрешённый бинарник | Проверить точные аргументы, владельца, окружение и связанный исполняемый код |
| В SUID найдена нестандартная программа | Проверить владельца, версию и поведение именно этой программы |
| Root-cron выполняет самописный скрипт | Проверить права на скрипт, его зависимости и рабочий каталог |
| Есть сервис только на `127.0.0.1` | Определить назначение и права доступа в рамках задания |
| Найден файл с названием `flag.txt` | Проверить, доступен ли он, относится ли к заданию и как это доказать |

## 7. Таблица воспроизводимых цепочек до флагов

**Пока не заполнена:** без исходного файла нельзя назвать конкретные команды и пути, *фактически давшие флаги* в прошлых финалах.

При добавлении writeup каждая цепочка заносится так:

| Поле | Что фиксировать |
|:--|:--|
| **Финал / год / задача** | Точное название из исходного разбора |
| **Точка входа** | Служба, адрес, URL или файл |
| **Первая находка** | Например, точная строка из `robots.txt` или вывод `sudo -l` |
| **Команда 1 → 2 → 3** | Реальные команды **в том же порядке**, что привели к результату |
| **Почему сработало** | Уязвимость / ошибка конфигурации / логическая цепочка |
| **Где лежал флаг** | Конкретный путь, endpoint или иной источник |
| **Подтверждение** | Фрагмент вывода без секретов, ссылка на источник / скриншот |
| **На что обобщается** | Класс проверок, применимый к следующему финалу |

> [!TIP]
> **Пример формата, не результат финала:** `GET /robots.txt → Disallow: /hidden/ → GET /hidden/ → доступный файл`. Пока отсутствует первоисточник, такую запись нельзя отмечать как «флаг найден».

### Обозначения источников для следующих версий

- **`[CHECK]`** — типовая проверка, ещё не подтверждённая writeup.
- **`[SEEN]`** — путь / команда явно присутствует в исходном разборе.
- **`[FLAG]`** — исходник доказывает, что действие привело к флагу.
- **`[HYPOTHESIS]`** — перспективный путь, но результата в источнике нет.

**Правило редакции:** не повышать `[CHECK]` до `[SEEN]` или `[FLAG]` без воспроизводимого доказательства. Команды и конкретные пути из следующих финалов добавлять как новые подтверждённые цепочки, не переписывая историю предыдущих.
